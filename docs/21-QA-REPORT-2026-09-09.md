## Manual / heuristic review

**Component toolkit (main focus this session)**
- Detail modal opens from any card; ‹ › arrows, ←/→ keys, and swipe all page
  through the filtered list in visible order (hardware → software).
- Position counter `n/total` reflects the active filter set.
- Back button + right-swipe both close; Esc + backdrop click also close.
- Mobile: visual is height-capped (`h-44`/`h-56`), single column, sticky top bar
  — the previous large empty square below short content is gone.
- Body scroll locks while open; scroll resets to top on each component change.

**Navigation / buttons (de-duplication)**
- Fixed duplicate ✨ icon: `/new` → 🆕, `/check` → 🛡️ (previously both ✨,
  colliding with the toolkit "All" chip). Icons are now unique per destination.
- ComponentDetail: the ✕ close button is desktop-only; on phones the single
  "← Back" button + swipe are the one clear way out (no redundant control).
- Confirmed no data-bearing buttons (download, purchase, admin approve/reject,
  bookmark/compare/collection) were changed — **no original data touched.**

## Known non-issues / by design
- `/toolkit` first-load JS is larger (static component catalogue) — acceptable;
  it is a client-side, offline-capable library.
- Some non-Arduino boards keep native code languages (Python/MicroPython) and
  industrial parts keep descriptive langs — intentional, documented in doc 20.

## Verdict
No regressions found. All automated gates green; the toolkit UX issues reported
